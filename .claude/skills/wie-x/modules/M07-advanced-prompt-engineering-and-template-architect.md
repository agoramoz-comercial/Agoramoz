### 7.4 Prompt Optimization

Evaluate:

- Clarity.
- Precision.
- Completeness.
- Logical consistency.
- Instruction hierarchy.
- Context efficiency.
- Token efficiency.
- Executability.
- Tool compatibility.
- Safety.
- Reusability.
- Testability.
- Recovery.
- Quality.

Remove:

- Redundant instructions.
- Contradictions.
- Unnecessary repetition.
- Decorative complexity.
- Unsupported capabilities.
- Unbounded loops.
- Ambiguous commands.
- Excessive role duplication.

Never optimize tokens by removing essential research, security, requirements or verification.

### 7.5 Prompt Engineering Test Bench

For substantial prompts, test:

- A. Normal scenario
- B. Ambiguous input
- C. Incomplete requirements
- D. Complex project
- E. Limited tools
- F. Token-constrained environment
- G. Conflicting requirements
- H. Security-sensitive scenario
- I. Interrupted execution
- J. Failed implementation
- K. Existing legacy project
- L. Novice user

Record:

- Test ID.
- Scenario.
- Expected behavior.
- Actual behavior.
- Result.
- Failure.
- Severity.
- Correction.
- Retest.

Never claim that a prompt was tested when it was only reviewed theoretically.

### 7.6 Prompt Red Team

Ask:

- Can the system misunderstand the objective?
- Are requirements missing?
- Are instructions contradictory?
- Can tool limitations cause false claims?
- Can it become stuck?
- Can it skip tests?
- Can it produce insecure output?
- Can it lose context?
- Can it perform unsafe actions?
- Are outputs measurable?
- Can completion be verified?
- Can the prompt be reused safely?

Correct critical weaknesses before qualification.

### 7.7 Prompt Versioning

Every substantial prompt must have:

- Prompt ID.
- Prompt Name.
- Version.
- Creation Date.
- Last Update.
- Original Prompt.
- Current Master Prompt.
- Change History.
- Change Rationale.
- Test Results.
- Scores.
- Limitations.
- Platform Compatibility.
- Qualification Status.

Never overwrite a successful prompt without retaining previous versions.
