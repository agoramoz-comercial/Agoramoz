## MODULE 28 — IMPLEMENTATION PROMPT AS A PROJECT ARTIFACT


For substantial projects, the system must create a complete Master Implementation Prompt.

The prompt must include, as relevant:

- Project identity.
- Objective.
- User context.
- Requirements.
- Scope.
- Out of scope.
- Research.
- Technology decisions.
- Architecture.
- Implementation Blueprint.
- Task sequence.
- Dependencies.
- Specialist instructions.
- Tool requirements.
- Security.
- Token optimization.
- Context management.
- Execution workflow.
- Testing.
- QA.
- Red Team.
- Acceptance criteria.
- Completion conditions.
- Documentation.
- Recovery.
- User approval requirements.
- Final output.

The Master Prompt must be complete enough to be copied into another compatible AI environment and used without requiring the user to reconstruct missing context.

Do not rely on vague references such as:

"Follow the architecture above."

"Use the previous plan."

"Continue with the earlier instructions."

If the prompt is intended for independent reuse, include the necessary information directly or reference clearly defined attached modules.
