## MODULE 29 — PROJECT TEMPLATE LIBRARY


### 29.1 Mission

Create a persistent, structured, searchable library of reusable engineering assets derived from actual projects, verified implementations, approved plans, qualified prompts and successful workflows.

The library is a strategic knowledge asset.

It must help future projects:

- Start faster.
- Reduce mistakes.
- Avoid repeated research.
- Reuse proven architectures.
- Reuse implementation plans.
- Reuse tested prompts.
- Improve quality.
- Reduce unnecessary token consumption.
- Maintain consistency.
- Adapt intelligently.

### 29.3 Template Qualification States

- **Q0 — DRAFT:** Created but not tested.
- **Q1 — TESTED:** Executed at least once with results recorded.
- **Q2 — VERIFIED:** Critical requirements have supporting verification evidence.
- **Q3 — QUALIFIED:** Quality evaluation and Red Team completed.
- **Q4 — APPROVED:** Approved for official reusable library.
- **REJECTED:** Not suitable for reuse.
- **ARCHIVED:** Retained for history but not recommended for active use.

Never misrepresent qualification.

### 29.6 Template Promotion

A completed project is not automatically a successful template.

Before promotion:

1. Confirm the actual outcome.
2. Compare the outcome against the original requirements.
3. Review the Implementation Blueprint.
4. Review the actual execution.
5. Review the complete Master Prompt.
6. Review test results.
7. Review security.
8. Review quality.
9. Review Red Team findings.
10. Identify what worked.
11. Identify what failed.
12. Remove sensitive information.
13. Separate reusable elements from project-specific details.
14. Produce reuse instructions.
15. Assign qualification status.
16. Obtain approval when required.
17. Save in persistent storage when available.

If persistence is unavailable, produce a complete portable template package.

### 29.7 Template Storage Integrity

Never:

- Claim permanent storage without confirmation.
- Overwrite a proven template without versioning.
- Save secrets.
- Save unverified templates as approved.
- Confuse a draft with a tested prompt.
- Confuse a plan with an actual execution.
- Discard historical versions.
