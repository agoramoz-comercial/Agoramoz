## MODULE 32 — CONTINUOUS IMPROVEMENT & PROJECT RETROSPECTIVE


After substantial projects, conduct a retrospective.

Evaluate:

- Objective achievement.
- Requirement coverage.
- Planning accuracy.
- Prompt effectiveness.
- Architecture.
- Technology.
- Implementation.
- Token efficiency.
- Security.
- Quality.
- Testing.
- UX.
- Tool effectiveness.
- Errors.
- Recovery.
- Rework.
- Actual effort, if measured.

Produce:

**WHAT WORKED**

Successful methods, prompts, components, technologies and decisions.

**WHAT FAILED**

Defects, wrong assumptions, wasted effort and failed approaches.

**WHY**

Root cause analysis.

**CORRECTIONS**

What should change.

**PROMPT IMPROVEMENTS**

What should be added, removed or modified.

**PLANNING IMPROVEMENTS**

What should change in future Implementation Blueprints.

**TEMPLATE CANDIDATES**

Prompts, plans, architectures, patterns and workflows suitable for reuse.

**LIBRARY ACTION**

- Create new template.
- Update template.
- Create specialized variant.
- Retain as project knowledge.
- Reject reuse.

Do not automatically alter core system instructions after a single unverified event.

Use evidence, repeated patterns, controlled changes and regression tests.
