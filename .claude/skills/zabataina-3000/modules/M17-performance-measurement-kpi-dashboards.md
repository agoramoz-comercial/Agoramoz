## SECTION 002 — KPI ARCHITECTURE

### 002.1 — KPI hierarchy

| Level | Purpose | Examples |
|---|---|---|
| North Star | Single measure of progress toward the mission | Track A–D value vs target |
| Financial KPIs | Economic results | Revenue, gross margin, net profit, cash, ARR |
| Driver KPIs | Revenue engine performance | Leads, opportunities, win rate, AOV, churn, CAC, LTV |
| Operational KPIs | Delivery and quality | Capacity utilization, on-time delivery, defects |
| Initiative KPIs | Progress of priority initiatives | Milestones, experiment results |

### 002.2 — Leading and lagging indicators

Lagging indicators (revenue, profit) confirm results. Leading indicators (qualified opportunities, proposals sent, activation rate) predict them. Every lagging KPI must have at least one leading KPI that the team can influence weekly.

### 002.3 — KPI definition card


### 002.4 — KPI selection rules

1. Maximum 5–7 KPIs on the executive dashboard.
2. Each KPI linked to a target track or the binding constraint.
3. Definitions fixed; changes recorded with date and reason.
4. Data source identified and reliable.

## SECTION 004 — REPORTING STANDARDS

### 004.1 — Report types

| Report | Frequency | Audience |
|---|---|---|
| Mission dashboard | Weekly | Owner / leadership |
| Initiative status | Weekly | Initiative owners |
| Monthly performance report | Monthly | Owner / board / investors |
| Gate review | Per gate | Decision owner |

### 004.2 — Monthly performance report structure

```
1. Executive summary (results, key decisions)
2. Track A–D: actual vs plan vs target, with variance
3. Variance analysis: causes (evidence) and actions
4. Revenue engine and unit economics
5. Cash and forecast update
6. Initiatives: status and results
7. Risks and issues
8. Updated forecast (scenarios)
9. Decisions required
```

### 004.3 — Variance analysis

```
Variance = Actual − Plan
Variance % = (Actual − Plan) ÷ Plan
```

Decompose revenue variance into volume, price and mix effects where data allows. Explain material variances with evidence, not narrative.

### 004.4 — Reporting integrity

1. Report bad news as clearly as good news.
2. Never change definitions to improve the appearance of results.
3. Separate actuals, forecasts and targets visibly.
4. Never report EXECUTED or VERIFIED without evidence (Module 01, Section 009.4).

## SECTION 005 — DATA QUALITY

1. Single source of truth per metric.
2. Reconciliation of key figures with accounting and bank data monthly.
3. Documentation of data collection methods.
4. Flag estimates and incomplete data.

---

## SECTION 006 — DASHBOARD IMPLEMENTATION

Start with a simple spreadsheet if data systems are immature; move to automated BI dashboards once data sources are reliable (Module 13). Visual design: clear targets, trends over time, red/amber/green status, minimal decoration.

Report truth, especially when it is uncomfortable.

Turn every red indicator into a decision.
