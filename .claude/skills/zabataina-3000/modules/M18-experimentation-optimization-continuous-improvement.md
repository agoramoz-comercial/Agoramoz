## SECTION 002 — EXPERIMENT DESIGN

### 002.1 — Experiment card (extended)

```

Result:

```

### 002.2 — Design rules

1. One primary metric per experiment.
2. Define success and failure thresholds before starting.
3. Define the minimum sample before reading results; do not stop early on promising noise.
4. Change one major variable at a time when traffic allows; with low volume, test bold differences rather than small tweaks.
5. Record every experiment, including failures.

### 002.3 — Small-sample realism

Many businesses lack the volume for statistically significant A/B tests. In that case, use: larger effect sizes, sequential pilots, qualitative evidence (customer conversations), and explicit confidence labeling. Never claim statistical significance that was not calculated.

## SECTION 003 — EXPERIMENT PRIORITIZATION

Score candidate experiments with ICE:

```
ICE = Impact (1–10) × Confidence (1–10) × Ease (1–10) ÷ 100
```

Run the highest ICE experiments that address the binding constraint (Module 02, Section 008). Limit simultaneous experiments to what the team can run and measure properly.

## SECTION 005 — LEARNING SYSTEM

### 005.1 — Weekly learning review

1. Experiments completed and results.
2. Decisions taken (scale / iterate / stop).
3. Key learnings about customers, channels and offer.
4. Next experiments queued.

### 005.2 — Learning library

Maintain a searchable record of all experiments and learnings. Before proposing a new experiment, check whether it has already been run.

### 005.3 — Post-mortems and retrospectives

After each phase and each major failure: what went well, what did not, root causes, and changes to the system. Apply Module 02, Section 013.3.

## SECTION 006 — CONTINUOUS IMPROVEMENT CULTURE

1. Small improvements every week compound.
2. Everyone can propose improvements; evidence decides.
3. Failure in a well-designed experiment is learning; failure to measure is waste.
4. Standardize what works (Module 12 SOPs) so improvements persist.
